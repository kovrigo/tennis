# План первой версии: сайт Федерации тенниса ЛО

Бриф, истории, объём, дизайн и разработка одобрены. Здесь — что строим, в каком порядке, какие файлы и как проверяем. Решения разработки в этом плане не меняются. Он их раскладывает на задачи.

## Итог

- Решений руководителя не требуется. Бриф не меняется.
- Новых зависимостей нет. Шрифты Onest и Oswald кладутся в репозиторий файлами.
- Строим всё из объёма за один заход: сервер, база, образцы, публичные страницы, экраны организатора и судьи, протокол.
- Порядок: основа и счёт, затем сервер и экраны параллельно, затем сборка целиком и проверка.
- Проверка: затронутые файлы тестов по именам и сборка. Весь набор тестов — один раз при выпуске.

## Что уже есть

- `server/index.ts`: HTTP-сервер, Vite в разработке, `dist/` в рабочем режиме. Остаётся, получает запуск базы, обновлений и образцов.
- `server/api.ts`: только `/api/health`. Заменяется таблицей маршрутов. Чтение коммита из git переносится как есть.
- `server/api.test.ts`: приём «обработчик на порту 0» сохраняется во всех тестах API.
- `src/App.tsx`, `src/main.tsx`, `src/index.css`: заготовка. `App.tsx` и стили пишутся заново, `main.tsx` остаётся.
- `.staging-site.json`, `.paneweb.json`: не меняются. Скрипты `dev`, `start`, `test` в `package.json` получают флаг против предупреждения `node:sqlite`.
- Прототип: цвета, шрифты, шапка, карточки, строка матча, таблица рейтинга, полоса дней, плашка, подвал, герб. Стили переносятся из него, убранное по дизайну не переносится.

## Устройство

```
браузер ── страницы React (src/) ── fetch /api/* ──┐
                                                  ▼
node:http ── server/index.ts ── createApp ── таблица маршрутов
                                   │            │ роль: public / organizer / judge
                                   │            ▼
                                   │      обработчики ── функции сохранения ── server/db.ts ── data/tennis.sqlite
                                   │            │                                            data/files/*
                                   │            └── представления страниц ── scoreFromActions
                                   └── при старте: обновления базы → образцы → приём запросов
```

- Один процесс, одна база SQLite, синхронные запросы. Каждая запись — одна транзакция.
- Функции сохранения — одни для форм, судьи и образцов. Проверка полей — в них же.
- Представления страниц собирает сервер: один запрос — одна страница. Московские время и дата для показа — тоже с сервера.
- Счёт не хранится. Его считает `scoreFromActions` по журналу действий судьи. Состояние, начало и конец матча пишет одна функция `recomputeMatch` в той же транзакции.

### Действие судьи

```
нажатие ─► блок кнопок ─► POST /api/judge/matches/:id/actions {requestId, type, side, expectedSeq}
                              │
          ┌───────────────────┴──── одна транзакция ───────────────────────────────┐
          │ 1 матч мой? итога вручную нет?        нет ─► 403 not_your_match / 409 manual_result
          │ 2 requestId уже есть?                 тот же ─► 200 текущий счёт; другой ─► 400
          │ 3 expectedSeq = последний seq?        нет ─► 409 stale + текущий счёт
          │ 4 очко после конца / отмена без очков ─► 409 finished / nothing_to_undo
          │ 5 отмена после конца на другой день   ─► 409 undo_closed
          │ 6 запись seq+1, recomputeMatch        ─► 200 {score, seq}
          └────────────────────────────────────────────────────────────────────────┘
ответ ─► табло = счёт с сайта; нет ответа 10 с ─► «Не сохранено», «Отправить снова» тем же requestId
```

### Состояние матча

```
not_started ──первое очко──► running ──последнее очко матча──► finished
     ▲                          │  ▲                              │
     └──отмена первого очка─────┘  └──────отмена (тот же день)────┘
любое ──итог вручную──► finished (manual) ──снять итог──► по журналу судьи
```

## Задачи

Каждая задача кончается работающим кодом и своими тестами.

### T1. Основа сервера

- База, обёртка, `tx` с точками сохранения, порядок обновлений с копией базы, `drift`, проверка состояния, 503 `not_ready` при сбое.
- Обработчик в одном `try/catch`: неверный адрес — 400, прочее — 500 без внутренностей. Заголовки `no-store`, `nosniff`, `DENY`. Тело JSON до 1 МБ.
- Отсутствующий файл под `/assets/` — 404. Заголовки `nosniff` и `DENY` — и у страниц.
- `/api/site`: контакты для подвала и вошедший сотрудник.
- Журнал: строка старта, каждое применённое обновление и образец, каждая ошибка 500 со стеком. `unhandledRejection` и `uncaughtException` пишутся в журнал. По `SIGTERM` база закрывается.
- Тесты: `server/migrate.test.ts`, `server/api.test.ts`.

### T2. Счёт и протокол

- `scoreFromActions`: до двух сетов, сет до 6 с разницей в два, тай-брейк до 7 при 6:6 в каждом сете, «больше-меньше». Отмена снимает последнее очко.
- Запись сетов со стороны победителя «6:4, 6:7(5), 7:6(3)», ход по геймам, тай-брейк одной клеткой с очками под ней.
- Судьи протокола — все, чьи очки засчитаны. Начало и конец — первое и последнее засчитанное очко.
- Тесты: `server/score.test.ts`.

### T3. Вход и права

- Пароли `scrypt`, подставной хеш для неизвестного логина, сессия в cookie `tennis_session_<PORT>`, продление не чаще раза в час, выход.
- 5 неверных попыток — 15 минут закрыто, 429 с числом минут. Попытка засчитывается до проверки пароля и снимается при верном. Так 20 одновременных попыток не обходят ограничение.
- Пароль хешируют обработчик входа и формы судьи до транзакции. Функции сохранения получают готовый хеш. Образцы хешируют синхронно при старте.
- Таблица маршрутов с ролью. Запросы `POST` и `PUT` принимают только тело `application/json`, кроме загрузки положения. `DELETE` идёт без тела. Выход шлёт `{}`.
- Тесты: `server/auth.test.ts`: каждый маршрут, 20 одновременных неверных паролей, срок сессии 24 часа и продление, заголовок `no-store`.

### T4. Турниры и положения (организатор)

- Список, форма, создание с `requestId`, исправление, удаление турнира без матчей.
- Новые даты не охватывают матчи — отказ с текстом из дизайна.
- Положение: загрузка до 20 МБ, PDF или Word, проверка первых байтов, скачивание с русским именем. Убрать нельзя, пока есть таблицы очков.
- Тесты: `server/files.test.ts`, `server/admin.test.ts`.

### T5. Разряды, таблицы очков, места, группы (организатор)

- Разряд: название, группа, строки таблицы с `id`. Группа обязательна при таблице. Таблица без положения — отказ. Строку с местами убрать нельзя.
- У разряда впервые появилась таблица — места текстом снимаются.
- Места: игроки из матчей разряда, место из строк таблицы или текстом, одно место нескольким игрокам.
- Группы: список и форма, без удаления.
- Тесты: `server/rating.test.ts`, `server/admin.test.ts`.

### T6. Игроки, матчи, судьи, итог вручную (организатор)

- Игроки: форма, предупреждение о совпадении без учёта регистра и «ё», удаление игрока без матчей.
- Матч: разряд, круг, день в датах турнира, время, корт, два разных игрока, судья. Исправление начатого матча счёт не трогает. Удаление матча без засчитанных очков.
- Новый игрок прямо из формы матча сохраняется вместе с матчем, в одной транзакции. Совпадение — то же предупреждение и повтор с подтверждением. Не сохранился матч — не появился и игрок.
- Игрок ушёл из разряда — его место снимается.
- Смена судьи: новый продолжает с текущего счёта, прежний получает отказ.
- Итог вручную: победитель обязателен, сеты и пометка по желанию. Сеты вводятся в порядке игроков матча. Если сеты введены, победитель должен выиграть больше сетов. Снять итог — матч возвращается к счёту судьи.
- Судьи: форма, логин уникален, новый пароль удаляет сессии судьи.
- Тесты: `server/admin.test.ts`, `server/actions.test.ts`.

### T7. Новости и контакты (организатор)

- Новости: список, форма, удаление. Дата по умолчанию — сегодня.
- Контакты: адрес, телефон, почта для подвала.
- Тесты: `server/admin.test.ts`.

### T8. Экраны судьи

- «Мои матчи»: не завершённые прошлых дней, сегодня, завтра и дальше.
- «Счёт матча»: табло, две кнопки очка, отмена, сообщения, повтор тем же `requestId`, плашка при устаревшем счёте, вход прямо на экране при истёкшей сессии, отмена после конца до конца дня.
- Экран не гаснет, если браузер позволяет.
- Под кнопками до первого очка — формат матча (S9.4). Сообщения читаются программой чтения с экрана.
- Тесты: `server/actions.test.ts`, с моментами вокруг московской полуночи. Экран проверяется в браузере.

### T9. Каркас и публичные страницы турниров

- Верхняя строка с пометкой «Тестовый сайт. Данные — образцы», шапка, меню, подвал с контактами, вход для сотрудников.
- Главная, календарь, страница турнира с полосой дней, матчами по кортам и итогами по разрядам.
- У каждой таблицы очков на тестовом сайте — плашка «Образец, не положение». Рядом — ссылка на положение.
- Состояния: загрузка, ошибка с кнопкой «Обновить», «Такой страницы нет». Общий перехватчик ошибок страницы показывает «Не удалось загрузить страницу» и «Обновить», а не пустой экран.
- Доступность: ссылка «К содержанию», области страницы, видимый фокус, мигание выключено при уменьшении движения. Заголовок вкладки — «Название — Федерация тенниса ЛО».
- Тесты: `server/dates.test.ts`, с моментами вокруг московской полуночи.

### T10. Онлайн-счёт

- `GET /api/live`: идут сейчас (в том числе с прошлых дней), ещё не начались, завершены сегодня, московское время ответа.
- Страница и блок на главной: опрос каждые 10 секунд от начала прошлого, ожидание 8 секунд, «Нет связи» после 30 секунд, пауза в скрытой вкладке. Плашка «Нет связи» озвучивается при появлении и исчезновении. После полуночи день меняется по ответу сервера.
- Тесты: `server/dates.test.ts`.

### T11. Рейтинг и игрок

- Сумма очков по группе за всё время, места 1, 2, 2, 4, равные по алфавиту, игроки без очков не входят.
- Страница игрока: суммы и места по группам, турниры с местом, очками, ссылками на таблицу и положение.
- Об игроке показаны только имя, фамилия и город. Других полей у игрока в базе нет.
- Имя игрока на всех публичных страницах — ссылка на его страницу.
- Тесты: `server/rating.test.ts`.

### T12. Новости

- Список от новых к старым, страница новости с абзацами.
- Тесты: `server/admin.test.ts` (сохранение и порядок).

### T13. Протокол

- Страница протокола без меню, кнопка «Распечатать», печать на одном листе A4.
- Матч идёт, итог вручную, матч не начат — по дизайну.

## Решения, принятые при проверке плана

Решения разработчика, а не руководителя. Каждое закрывает найденный пробел в пределах объёма.

- Итог вручную пишет в матч состояние `finished`, но не время конца. Снятие итога пересчитывает состояние по журналу. Так онлайн-счёт и списки не ищут итоги отдельно.
- «Завершены сегодня» — матч завершён и назначен на сегодня, или судья закончил его сегодня. Итог прошлого матча, внесённый сегодня, сюда не попадает.
- Судья может вести свой матч и раньше его дня. Расписание на корте часто сдвигается.
- Предупреждение о совпадении игрока — и при добавлении, и при исправлении.
- Строка матча собирается одной функцией сервера для главной, онлайн-счёта, турнира и судьи. Имена «Фамилия И.» и полные при совпадении — там же.
- Онлайн-счёт читает журнал действий одним запросом на все нужные матчи, без запроса на каждый матч.
- Время, когда судья мог отменить очко, проверяет сервер. Экран только показывает ответ.
- Пустая строка контактов создаётся обновлением базы. Сами контакты-образцы — образцами.
- Протокол и строка матча берут счёт итога вручную со стороны победителя, как счёт судьи.
- Номер запроса (`requestId`) строится из `crypto.getRandomValues`: `crypto.randomUUID` есть только на https и localhost.
- Сервер, общие детали страниц и типы API пишутся в основном потоке. Параллельные потоки получают по папке экранов и в чужие файлы не пишут.
- Имена «Фамилия И.» и полные при совпадении собирает только сервер. Месяцы «сен», «окт» — своя таблица, не `Intl`: он даёт «сент.».

Не принято:

- Отдельные рабочие копии для потоков. Задача работает в одной копии. Потоки делят её и пишут в разные папки.
- Сравнение версии вкладки с версией сайта. Первая версия меняет API только добавлением полей. Общий перехватчик ошибок закрывает остальное.
- Номера записей, созданные страницей, вместо `create_requests`. Решение разработки остаётся.

## Возможные сбои

- Выпуск во время матча: сайт стоит около минуты. Судья видит «Не сохранено», отправляет снова. Повтор не задваивает очко. Тест — `actions`.
- Два телефона у одного судьи: второе нажатие по старому счёту отклоняется с текущим счётом. Тест — `actions`.
- Обновление базы упало: сайт отвечает 503, выпуск это видит, база откатывается. Тест — `migrate`.
- Образцы упали: сайт работает, проверка состояния показывает ошибку. Тест — `migrate`.
- Файл положения пропал с диска: скачивание — 404, страница турнира открывается. Тест — `files`.
- Вкладка со старой версией после выпуска: ответ API не совпал с ожидаемым — общий перехватчик показывает «Не удалось загрузить страницу» и «Обновить». Новые файлы `/assets/` старой версии дают 404. Тест — `api`.
- Двадцать одновременных неверных паролей: после пятого — 429. Тест — `auth`.
- Сессия истекла в форме организатора: введённое остаётся, ссылка на вход в новой вкладке. Проверяется в браузере.
- Неверный адрес с битой кодировкой: 400, процесс не падает. Тест — `api`.

Тихих сбоев без теста и без сообщения не найдено.

## Порядок сборки

1. Основа, в основном потоке:
   - T1, T2, схема, типы API;
   - функции действия судьи и `recomputeMatch`, рейтинг, группы календаря и онлайн-счёта;
   - общие детали страниц: маршрутизатор и таблица адресов, запросы, строка матча, карточка турнира, состояния загрузки и ошибки, детали форм организатора, каркас, стили, шрифты.
2. Параллельно, в одной рабочей копии, разные папки:
   - основной поток: весь сервер — T3–T13 и проверки к ним;
   - экраны: публичные и протокол (`src/pages/public/`);
   - экраны: организатор (`src/pages/admin/`);
   - экраны: судья и вход (`src/pages/judge/`).
3. Образцы T14 — после функций сохранения, в основном потоке.
4. Сборка целиком: чистая база, сайт разработки, вход образцами, проход по каждой истории, проверка в браузере, исправления.
5. Проверка: затронутые тесты по именам, `bun run build`.

Потоки экранов не меняют `src/api-types.ts`, общие детали и сервер. Нужна правка — её делает основной поток.

## Не входит

- Всё из раздела брифа «Что позже» и из раздела дизайна «Не входит».
- Браузерные тесты в репозитории — решено в разработке; экраны проверяются на следующих этапах.
- Резервные копии по расписанию, флаг `Secure`, ограничение входа по адресу — к публичному запуску.
- Проверка версий при одновременной правке организатором — сохраняется последнее, роль одна.

## Риски

- Объём большой: около 40 экранов и 60 маршрутов. Риск — неровности на экранах. Их ловят визуальная проверка и тестирование.
- `node:sqlite` в Node 22 экспериментальный. Всё обращение к нему — в `server/db.ts`.
- Загрузка положения на 20 МБ через прокси тестового сайта до выпуска не проверена. Проверка — на этапе тестирования.
- Образцы выполняются один раз на базу. Ошибку в образцах на тестовом сайте исправляет только новый файл образцов.
- Даты образцов отсчитаны от первого запуска. Через несколько дней на тестовом сайте нет сегодняшних матчей образцов. Для проверки онлайн-счёта организатор вносит матч на сегодня или проверка идёт на сайте разработки с чистой базой.
