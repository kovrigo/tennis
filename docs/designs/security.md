# Проверка безопасности

Проверена вся ветка задачи на последнем коммите, вместе с исправлениями код-ревью и второго мнения. Код прочитан целиком: сервер, база, образцы, страницы. Защита проверена запросами на своём сайте разработки. У общего тестового сайта проверены адрес, шифрование и запуск. На нём пока прежняя версия основной ветки: эта ветка туда ещё не выпускалась.

## Итог

- Уязвимостей, которыми можно воспользоваться, не найдено.
- Слабые места, которые на тестовом сайте использовать нельзя, перечислены в рисках для запуска.
- HTTPS на тестовом сайте есть. Сайт открыт только в частной сети команды, из интернета недоступен.
- Пароли образцов есть только в образцах, тестах и документах разработки. В страницы сайта они не попадают. Но образцы создаются в каждой новой базе, не только на тестовом сайте.
- Попутно исправлен тест, который сломало ограничение турнира в 400 дней из прошлого этапа. Без исправления полный прогон тестов при выпуске упал бы.
- Решений сейчас не требуется.

## Ответы на вопросы задания

### Пароли образцов

- Учётные записи `organizer`, `judge1` и `judge2` создаёт только файл образцов. Их пароли ещё записаны в тестах, в README и в документе разработки.
- В собранных страницах сайта паролей нет. В истории репозитория нет ключей и секретов.
- Образцы создаются при первом запуске любой новой базы: на сайте разработки, на тестовом и на будущем рабочем сайте. Отдельной проверки «это тестовый сайт» нет.
- Так решено в разработке: до запуска образцы убирает новый файл обновления. Пароли записаны в документах открыто. Поэтому рабочий сайт нельзя открывать, пока образцы не удалены.

### HTTPS

- Тестовый сайт открывается по https на адресе частной сети. Сертификат Let's Encrypt действителен до 8 декабря 2026 года.
- Шифрование даёт прокси частной сети. Сам сервер сайта слушает только внутренний адрес машины, по обычному http.
- Обычный http на том же порту не работает: прокси отвечает ошибкой, а не страницей.
- Публикация в интернет выключена.
- Сайт разработки тоже слушает только внутренний адрес машины.
- В отчёте код-ревью сказано, что тестовый сайт работает без https. Это неверно. Комментарий в коде с той же ошибкой исправлен.

## Что проверено и держится

1. Доступ организатора и судьи.
   - Любой закрытый адрес без входа отвечает 401, под другой ролью — 403. Тесты проверяют это по всему списку адресов.
   - Без входа можно только войти и выйти.
   - Судья отмечает очки только в своём матче. Другой судья и организатор получают отказ, журнал счёта не меняется.
   - Через форму судьи нельзя изменить учётную запись организатора.
2. Вход и сессии.
   - Пароли хранятся хешем со случайной солью. По времени ответа нельзя узнать, есть ли такой логин.
   - Сессия — 32 случайных байта, в базе лежит только её хеш. Скрипты страницы не видят cookie входа.
   - Пять неверных паролей закрывают логин на 15 минут. Параллельные попытки этот предел не обходят.
   - Выход и новый пароль судьи завершают сессии.
3. Подделка запросов с чужого сайта.
   - Все изменения принимаются только в формате JSON. Чужая страница не может отправить такой запрос без разрешения сервера, а сервер его не даёт.
   - Формы и простой текст отклоняются, в том числе при выходе.
   - Сайт нельзя встроить в чужую страницу.
4. Файлы положений.
   - Принимается только PDF или Word: по расширению и по первым байтам файла. Не больше 20 МБ, только от организатора.
   - Файл хранится под случайным именем. Имя от организатора очищается и попадает только в заголовок скачивания.
   - Файл всегда скачивается, браузер не открывает его как страницу.
   - Выйти за папку файлов или папку сборки нельзя. Сайт разработки не отдаёт базу и черновики.
5. Ввод и база.
   - Все запросы к базе идут с параметрами, текст в них не подставляется. Внедрения SQL нет.
   - Сервер сам проверяет поля: длину, даты, номера, ссылки только на свои записи.
   - Страницы не вставляют присланный текст как разметку. Ссылки на почту и телефон собираются из проверенных значений.
   - Изменения идут в транзакциях. Перед обновлением схемы база копируется.
6. Счёт.
   - Очки только добавляются в журнал, счёт пересчитывается из него. Повтор не засчитывается дважды, действие по устаревшему счёту отклоняется.
   - После итога вручную судья матч не ведёт. Отменить очко после конца матча можно только в тот же день.
   - Судья может вести свой матч в любой день, не только в день матча. Объём это не запрещает.
7. Секреты и журнал.
   - Файлов с ключами и настройками окружения в репозитории нет.
   - Журнал сервера пишет только метод и путь запроса, без cookie и заголовков. Это важно: на тестовом сервере браузер шлёт сайту и cookie других сайтов того же адреса.
   - Ошибка 500 не показывает внутренности сервера.
8. Зависимости.
   - Известных уязвимостей нет. У рабочих пакетов нет скриптов установки.
   - Версии закреплены в репозитории, тестовый сайт ставит их строго по списку.
9. Тестовый сайт работает от обычного пользователя, не от администратора машины.

## Оставшиеся риски для настоящего запуска

Объём уже требует к запуску убрать образцы, завести сотрудников, опубликовать политику данных и настроить резервные копии. Сверх этого:

1. Нужны свой домен и строгий https.
   - Сейчас все сайты тестового сервера живут на одном адресе с разными портами. Браузер отправляет cookie входа каждому из них.
   - Чужой сайт на том же адресе может получить вход организатора или подсунуть свой.
   - К запуску нужны отдельный домен, флаг Secure у cookie и строгий https на прокси.
2. Пароль организатора нельзя сменить, а его сессии нельзя завершить. Украденный телефон организатора даёт вход, пока им пользуются. К запуску нужна смена пароля организатора, которая завершает его сессии.
3. Вход закрывается по логину, а не по адресу. Любой может на 15 минут закрыть вход сотруднику с известным логином. К запуску нужно ограничение по адресу.
4. Хеш паролей слабее, чем советуют сейчас. При утечке базы простой пароль подберут быстрее. К запуску нужно поднять стоимость хеша.
5. База и её копии читаются любым пользователем машины. На тестовом сервере кроме сайта есть ещё две учётные записи. Пароли и сессии в базе хешированы, но остальные данные видны. К запуску нужны отдельный пользователь и закрытая папка данных.
6. У страниц нет политики источников (CSP). Способа вставить чужой код сейчас не найдено. К запуску она нужна как второй рубеж.
7. Проверка состояния сайта показывает текст ошибки запуска всем. К запуску его нужно скрыть от посетителей.
8. В репозитории нет автоматического поиска случайно добавленных ключей. Сейчас ключей нет. Он понадобится, когда появятся почта или оплата.
